# 0008 推理门禁：结论出口的第二道门

- 状态：已接受
- 日期：2026-10-26

## 问题

v3 的三道门禁全部挂在外部证据上：取到权威载体、可引用数值、条款编号，缺口就算闭合。它约束了"证据是否为真"，没有约束"从证据到因果的那一步"。

一次小样本失效：10 个客户，做过转介绍送体验，到店 1–2 人、未成交，客户互不认识。输出判定为"客户口碑结构性关闭，任何老带新都会重复失败"。

事实是 1–2 ÷ 10 ＝ 10%–20% 的转介绍率，与行业老带新率持平；转介绍在正常运作，失效的是转化率与基数。同一条证据支持两个结论，模型选了更有解释力的那个，没有算比值。状态却被标成「已闭合」。

这不是检索不足，是推理结构缺一道门：外部证据门禁无法发现"数据都对、因果推错"。

## 决策

在 `SKILL.md` §2 增加推理门禁，与三道缺口门禁并列。任何"因为 X 所以 Y"的判断，标「已闭合」前通过四项：

| 检查 | 判据 | 拦住的失效 |
|---|---|---|
| 关系式 | 写出量的关系（乘法、加法、阈值、比例） | 多个因子被压成一个原因 |
| 比率基准 | 判"失效"前算比率并与参照类比 | 用绝对量小证明机制失效 |
| 反证观测 | 写一条"若结论成立则不应出现"的现象 | 结论不可证伪 |
| 断言强度 | N≤2 只支持存在性 | 全称断言与机制性结论 |

结论分观测级、推断级、叙事级；只有前两级可以写「已闭合」，叙事级必须写「未判」。

细节、校准案例与失败签名在 [references/reasoning-gate.md](../../references/reasoning-gate.md)。

## 备选方案

- **监控层**：为每个决策埋指标，事后判断对错。否决理由：结果滞后（比率变化要数月到一年才能观测）、每个决策都要埋点、而这次失效发生在推理结构上而非数据缺失——数据齐全，只是没有算。监控解决"我不知道结果"，不解决"我把结果归错了因"。
- **只改措辞**：在提示词里写"要严谨、注意样本量"。否决理由：不可观察、不可评测，属于被 v1 诊断过的失效（叙述替代执行）。
- **加一条输出契约列（结论强度）**：否决理由：改输出契约属于 major，需要用户授权；且现有状态列已能承载三级强度，加列会同时改动下游解析与全部用例的 `must_match`。
- **并入证据缺失门禁**：否决理由：证据缺失管的是"答案取决于未来"，推理门禁管的是"已有数据推错因"。类型不同，合并会让已有数据的场景无处挂门禁。

## 后果

- 「已闭合」的含义变严：既要证据为真，也要因果可检。已有用例的门禁语义随之收紧，但输出契约、7 节结构与台账列不变。
- 交付会更保守：叙事级结论必须写「未判」，短期看像"不敢下结论"，长期减少整轮返工。
- 新增 case-09 约束该行为：小样本 ＋ 绝对量被当作机制失效的输入，输出必须出现比率、基数与反证观测之一。
- 剩余风险：推理门禁只能拦结构性可检的错误（量纲、基数、全称断言、输入矛盾），拦不住前提本身错——例如用户给的客户数、到店数本身不准。这类错误仍由执行记录里的"未验证"项承担。
