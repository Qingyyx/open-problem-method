# 0003 缺口台账取代六段模板

- 状态：已接受
- 日期：2026-10-25
- 后续：输出载体由 [0007](0007-process-document-output.md) 取代；台账列与一个下一步的规则继续有效。

## 问题

v1 的输出模板有六段：重构后的问题、形态判定、候选路径、中间物与自检、最便宜的第一步、最可能失败的位置。六段都是陈述句，可以在不跑任何探针的情况下写完。模板不要求状态、代价、证据来源、执行者或失败信号，因此无法证明输出背后有动作。

模板还要求「候选路径至少 3 条」。这条规则在两个方向上出错：对需要取舍的问题，它把选择责任推回用户；对门禁已经满足、不该继续拆解的问题，它只能继续编路径。case-07 覆盖后一种情况。

## 决策

输出改为缺口台账、一个下一步、停止条件与翻转信号。台账每行含缺口陈述（可判定）、类型、已过门禁、代价、状态。下一步含动作、执行者、工具、预计耗时、花费上限、失败信号。停止条件写明满足什么即停，或最多再做几次探针。

两条以上并列路径视为未完成。台账记录多个缺口，但一次只推进一个，由代价与不可逆性排序。

## 备选方案

- 保留六段模板：六段可以在不执行的情况下填写，且没有字段能证明执行；模板还强制并列路径，无法表达「不需要拆解」。
- 自由格式：无法稳定 grep，评测不能写可复现断言，评审也无法比较两次输出是否都执行了探针。
- 只给下一步：丢失多缺口共存与各自门禁状态；下一轮无法恢复上下文，也无法解释为什么先做这一步。
- 台账加并列方案：保留台账但允许两条以上路径，仍然把选择推回用户，case-07 的失败模式不变。

## 后果

输出可以被脚本按固定字段检查，状态与代价迫使执行留下痕迹；「停止」成为合法结论，而不是失败。

风险是台账退化为填表：类型与状态都写了，但没有真实动作。约束来自三处：缺口陈述必须可判定，下一步必须含执行者与失败信号，行为评测要求正向证据（标准号、数值、未判状态），而不是只看措辞。

字段的逐项定义见 `SKILL.md` 的输出契约，这里不复述。
