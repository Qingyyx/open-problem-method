# 0007 过程文档作为输出载体

- 状态：已接受
- 日期：2026-10-25

## 问题

v2 的输出是台账加一个下一步。它能证明有状态与代价，但不能证明过程可复查：读者看不到 P0 检索了什么、来源层级是什么、哪些结论没有验证。模型可以把多个步骤压成一段结论，仍然满足台账字段。

## 决策

输出载体改为过程文档，固定 7 个二级标题：问题与结论、P0 探针、缺口台账、实例化、下一步、停止与翻转、执行记录。台账仍是第 3 节。文档同时写入当前目录的 `open-problem-<slug>.md`；目录不可写时，回答正文就是同一份文档。

## 备选方案

- 只保留台账：字段可检查，但探针来源、未验证项与执行记录没有位置，过程仍不可复查。
- 自由格式的过程说明：每个模型写法不同，无法用固定标题解析，也无法写稳定的 `must_match`。
- 只落盘、不在回答里输出：宿主不可写时没有交付物；用户还要额外打开文件才能看到结论。
- 固定 7 节但允许合并：合并后又会回到"只写最终结果"，标题检查形同虚设。

## 后果

过程可复查，下游可按固定标题解析；代价是输出更长，且必须维护 7 节的模板。风险是文档变成填表：第 2、7 节最容易空泛。缓解是 case-08 检查 7 个标题都存在，人工评审检查第 2 节是否有来源层级、第 7 节是否有工具与未验证项。
