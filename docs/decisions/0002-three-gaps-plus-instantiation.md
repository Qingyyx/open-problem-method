# 0002 三个缺口与强制实例化

- 状态：已接受
- 日期：2026-10-25

## 问题

v1 有四个形态：检索、构造、匹配、实验。前三个各自对应一种「缺什么」：缺载体、缺中间物、缺未来证据。匹配对应的是「答案依赖谁来做」，它不是同一层的缺失。

判别器只有一条：一个缺口类型必须能作为最后一个缺口独立闭合。也就是说，当其他缺口都闭合后，剩下的那个类型仍然可以单独阻止给出下一步。定位缺失满足：没有载体就无法给出可引用结论。生成缺失满足：没有可检查的中间物就无法判断方案是否成立。证据缺失满足：没有可证伪断言与止损线就无法决定是否投入。适配不满足：答案不存在时，适配没有对象；答案存在时，适配只是在已有答案上过滤条件，不产生新的可检索或可验证对象。

因此适配不能作为缺口类型。它是对每条路径都适用的变换，而且几乎所有真实问题都需要它。把它留在类型表里，会让带个人条件的问题默认落进这个分支，跳过真正的定位、生成或证据缺口。

## 决策

类型收敛为三种缺口：定位缺失、生成缺失、证据缺失。适配改为强制步骤：实例化。

实例化不是可选补充。任何答案在交付前必须列出最多 5 条会翻转结论的私有条件，每条是数值或二值；缺哪一条就明说「无法决策」，并把它变成下一次探针。只给通用对比表或清单视为未完成。

## 备选方案

- 保留四型：适配会成为带个人条件问题的默认归类，而 v1 没有为它定义硬门禁，真实缺口因此被跳过。判别器已经说明它不能独立闭合。
- 改为四个补救动作：定位、构造、取证、适配。动作不是缺口，无法判断何时闭合；输出会变成流程清单，台账没有可写的状态。
- 只留门禁不分型：门禁仍可执行，但无法按缺口排序，无法把不同缺口路由到不同参考文件，也无法在台账里表达同一问题的多行。
- 把实例化并入证据门禁：定位与生成同样需要私有条件，合并会让定位分支合法地跳过实例化，回到通用答案。

## 后果

三种缺口覆盖可以独立闭合的缺失；实例化成为所有路径的统一出口。case-01 与 case-05 验证多缺口共存和私有约束：前者要求同时出现定位动作与预算、通勤、孩子条件，后者要求先出 workload 维度的私有数值（QPS、OLTP/OLAP、行数、延迟等）。

风险是实例化退化为「取决于你的需求」。门禁要求每条条件是数值或二值；case-05 要求台账保留未判或未闭合状态，说明约束尚未取到，而不是用一句「看需求」收尾。
